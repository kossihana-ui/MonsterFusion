# バトルの仕様と調整結果

[BATTLE_HANDOFF.md](../../MonsterFusion-UI/src/mocks/BATTLE_HANDOFF.md) の依頼に対する対応です。

## 1. 守るの発動タイミング（依頼1）

**ターンを「宣言」と「解決」の2段階に分けました。**

```
1. 宣言  全員が行動を決める。守るを選んだ者は この時点で防御態勢に入る
2. 解決  守る以外の行動を素早さ順に処理する
```

これにより、**遅い側が守っても先制攻撃を軽減できます**。以前は防御フラグが素早さ順の自分の番で立っていたため、「守るのが明らかに正しい場面」でだけ守るが機能しませんでした。

あわせて確定したこと:

- **ポリシーは1ターンに1回だけ呼ばれます。** 以前は解決ループ内で呼んでいたため回数が状況依存でした
- **判断材料はターン開始時の状態です。** 素早さ順のどこにいるかで見える情報が変わりません
- **MP回復は宣言の前**に行われます。ターン開始時の回復込みでMP充足を判断できます
- **守るとMPが回復します**（`defendMpBonus`、既定+4）。ターンを捨てる行動ではなく、技を溜める選択肢になります

宣言内容は `declareActions(state, policies)` で取得できます。敵の予備動作を表示したい場合に使えます（`stepTurn` は内部で同じものを使います）。

```ts
declareActions(state, policies);
// [{ actorId: '0-0:xxx', action: { kind: 'defend' } }, ...]
```

**UI側の説明文の更新をお願いします。** 「先制攻撃は防げません」は事実と異なるようになりました。

## 2. 戦闘のテンポ（依頼2）

### 変更前の実測

```
スターター総当たり   ターン中央値 2    5-8に収まる  0%
速度+10 の勝率      95%
守る                 価値なし（決着が早すぎて機能しない）
```

**素早さが先攻と会心率の両方に効き、2ターンで決着していました。**

### 変更内容

| 設定 | 変更 | 理由 |
|---|---|---|
| `damageScale` | 新規 **0.2** | ダメージ全体の倍率。テンポを決める唯一のつまみ |
| `initiativeVariance` | 新規 **0.25** | 行動順を素早さ±25%の抽選に。素早さは有利だが確定ではない |
| `criticalChancePerSpeed` | 0.002 → **0.0008** | 素早さが先攻と会心の両方を買う二重取りを縮小 |
| `criticalChanceCap` | 0.35 → **0.2** | 同上 |
| `offhandFactor` | 新規 **0.25** | 使わない方の攻撃能力も一部加算（後述） |
| 属性倍率 | 1.3/0.7 → **1.25/0.8** | 相性差が複合して約1.9倍になり、一方的になっていた |

### 変更後の実測

```
スターター総当たり   ターン中央値 4-6   5-8に収まる 37-97%
速度+10 の勝率      63%     （+40でも 75%）
守る                 常に守ると 5.8 → 13.9 ターン（約2.4倍）
```

同格の戦闘は**おおむね5〜8ターン**に収まります。素早さは有利ですが決定的ではなくなりました。

## 3. 能力値合計が強さを表していなかった問題

依頼の「世代差も検証する」で見つかった、より根本的な問題です。

**技は攻撃か魔法の一方しか参照しないため、もう片方の数値が完全に死んでいました。** 合計値で上回る融合体が、ステータスの振り分けが噛み合わず負ける状態でした。

2点直しました。

1. **技の参照能力を、傾向遺伝子ではなく実際の能力値で決める**ようにしました。世代5の個体は魔法87・攻撃83なのに攻撃参照の技を使っており、弱い方で殴っていました
2. **`offhandFactor`（既定0.25）** を導入し、使わない方の攻撃能力も25%加算されるようにしました

結果、合計値と勝率の相関が改善しました。

```
変更前: 合計428→勝率67%  合計398→勝率57%  合計408→勝率45%  （相関なし）
変更後: 合計424→勝率67%  合計420→勝率77%  合計397→勝率2%   （概ね相関）
```

**ただし完全な相関にはなりません。** HPと防御は攻撃より効率が良いため、同じ合計値でも振り分けで強さが変わります。これは設計上の性質であり、バグではありません。

## 4. スターターの均衡

総当たりで **Aqua > Ignis > Moss** の実力順が付いており、最弱のMossは勝率21%でした。能力傾向を探索で調整しました。

| | 攻撃 | 防御 | 魔法 | 速度 |
|---|---|---|---|---|
| Moss | 35→**45** | 55→**65** | 65→**60** | 35→**30** |
| Ignis | 70 | 50 | 30→**25** | 40→**35** |
| Aqua | 60→**70** | 35→**25** | 45→**35** | 60→**55** |

性格は維持しています（Moss＝防御的、Ignis＝最も火力が高い、Aqua＝最速）。50%からの最大乖離は29%→11%になりました。

**ただしシード集合によって Moss vs Ignis が22〜39%と振れます。** 完全な均衡ではありません。

## 5. 構造化ログ（依頼・API）

`BattleLogEntry` に追加しました。既存フィールドはそのままなので、互換性は保たれます。

```ts
{
  turn, actorId, targetId, kind, damage, critical, message,   // 既存
  skillId?: string,            // 使用した技
  elementMultiplier?: number,  // この一撃に適用された相性倍率
  mitigated?: number,          // 防御で軽減された量
  mpSpent?: number,            // 消費MP（守るによる回復は負値）
}
```

日本語の戦闘演出は、`message` を解析せずこれらの値から組み立ててください。

## 6. API

依頼どおり、既存の形は維持しています。

```ts
stepTurn(state, policies, rng, config?): BattleState      // 変更なし
elementMultiplier(attacker, defender, config?): number    // 変更なし
Combatant.skills: readonly Skill[]                        // 変更なし
```

追加したもの:

```ts
declareActions(state, policies): DeclaredAction[]   // 宣言内容だけ取得
expectedDamage(attacker, defender, skill?, config?): number  // 乱数抜きの期待値
offensivePower(attacker, skill?, config?): number   // 実効攻撃力
```

`expectedDamage` は技選択UIで「この技は何ダメージくらいか」を出すのに使えます。相性倍率も織り込み済みです。敵AIも同じ関数で技を選ぶので、表示と挙動が一致します。
