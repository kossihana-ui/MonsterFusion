# 匿名アカウントとセーブ同期

2026-11-15。順番の④です。

## 1. 何が問題か

セーブはブラウザのlocalStorageにしかありません。**端末を変えると全部消えます。**
スマホで育てた系譜はパソコンに来ませんし、ブラウザのデータを消せば終わりです。

⑤の連勝ランキングは、これがないと成り立ちません。**誰の記録なのかを言える
仕組みが先です。**

## 2. なぜ「ログイン」にしないか

名前とパスワードの登録画面は、**このゲームでは入口の壁**です。リンクから
一度試す人がほとんどで、フォームはそこで大半が止まる場所です。

なので**ブラウザが勝手にアカウントを作ります。** 何も聞きません。

- **ID**（10文字）… 公開してよい。ランキングの行を指すのはこれ
- **合言葉**（24文字）… これだけが「自分のアカウント」の証拠

この2つを繋げて印刷したのが**引き継ぎコード**です。

```
MF1-7K3M-QX9D-...
```

別の端末でこれを入れれば、同じアカウントになります。**「セーブを移す」とは
このゲームでは引き継ぎコードを運ぶこと**です。

### 決めたこと

- **見まちがえる文字を使いません。** `0 O 1 I L U` は英数字から外しました。
  画面から読んで別のスマホに打ち込む、が実際の使い方です
- **打ちまちがいは直しません。断ります。** `O` と打った人が `Q` を意図したのか
  `D` だったのかは分かりません。推測して別の合言葉を返すと、**動いている風に
  見えて動いていない**コードになります。どの文字が変かを言うだけにしました
- **合言葉はcrypto（暗号用乱数）から作ります。** `createCryptoEntropy()` です。
  「乱数は差し替え可能に」という普段の決まりが、ここだけは逆に働きます：
  seed付き乱数は**同じ合言葉を全員に配ります。** テスト用の
  `entropyFromRandom()` は名前で「本番で使ったら間違い」と分かるようにしました

## 3. 2台で遊んだときに何が起きるか（ここが本題）

**セーブのほとんどは合成できません。**

| 中身 | 合成できるか |
|---|---|
| `monsters`（これまで存在した全個体） | **できる。** 追加しかされない記録なので、和を取れば正しい |
| `inventory` / `items`（持ち物の数） | できない。足せば増殖、大きい方を取っても増殖 |
| `session.ownedIds`（まだ手元にいるのは誰か） | できない。片方で死んだ個体が片方で生きている |
| `session.status`（ゲームオーバーか） | できない |
| `arena`（進行中の連勝） | できない |

**「新しい方を採る」はやりません。** 2台の時計はずれます（寝ていたスマホは
特にずれます）。しかもこのゲームは**負けると個体を失う**ので、黙って片方を
消すのは、この層がやれる最悪のことです。

### 採った規則

```
系譜（monsters）は和を取る。
それ以外は、片方を丸ごと採る。どちらかはプレイヤーが決める。
```

新旧の判定は時計ではなく**カウンタ**です。

- `revision` … 書くたびに1つ増える
- `basedOn` … どの `revision` の上に書いたか

`basedOn` があるので**「分岐した」が見えます。** 2台がどちらも revision 1 の上に
revision 2 を書いたら、新しい方は存在しません。そのときは `'diverged'` を返し、
**このコードは選びません。** `describeChoice()` が「この端末には何がいて、
何連勝中で、ゲームオーバーか」を言葉にして返すので、画面はそれを並べて
プレイヤーに選ばせます。

どちらを選んでも、**相手側の個体が系譜から消えることはありません。**
手元にいなくなるだけです（融合で消えた親と同じ扱い）。

## 4. サーバは、まだ決めていません

`SaveTransport` は**口だけ**です。

```ts
export interface SaveTransport {
  pull(accountId: string): Promise<SyncEnvelope | null>;
  push(envelope: SyncEnvelope, secret: string): Promise<PushResult>;
}
```

2つしかありません。サーバでも、書き出したファイルでも、テスト用の
`createMemoryTransport()` でも、同じ形に収まります。**どこに置くかという
決定がゲームの規則に混ざらない**ようにするためです。

`push` が合言葉を受け取るのは、**向こう側が他人の書き込みを断れる必要がある**
からです。coreのそれ以外の場所は合言葉を見ません。

`PushResult` の `'stale'` は「先に誰かが書いた」で、引いて、決めて、もう一度
書きます。これはテストで確認しています。

### 置き場所の候補

いまGitHub Pagesは**静的配信**です。サーバはありません。つまり同期には
置き場所がもう一つ必要で、**ここはお金とアカウントの話になるので、
私では決められません。**

| | 作り | 無料の範囲 | 向いている点 |
|---|---|---|---|
| Supabase | Postgres + REST | 無料枠あり | 公開鍵（anon key）だけで書ける。⑤のランキングもSQLで済む |
| Cloudflare Workers + KV | 自分で書く小さなAPI | 無料枠が広い | 置くものが少ない。合言葉の検証を自分で書く |
| コード書き出しだけ | サーバなし | 0円 | 「引き継ぎコード＋セーブ文字列」を手で運ぶ。同期ではない |

**鍵はコードに書きません。** どれを選んでも、環境変数（Viteなら
`import.meta.env.VITE_*`）から読む形にします。Supabaseのanon keyは公開前提の
鍵ですが、それでもソースに直書きはしません。
