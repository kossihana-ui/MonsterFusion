# 競技性と戦略性を上げるには（測定つき）

2026-11-14。「競技性と戦略性を大きくするにはどうすればよいか」への回答です。推測ではなく、現在のコードを実際に走らせて測った数字から書いています。

## 1. 先に結論

**戦略性はすでに存在します。問題は、ゲームがそれを一度もプレイヤーに尋ねないことです。**

**競技性はまだ成立しません。** 敵がプレイヤーの強さに合わせて作られるため、「どこまで勝ち抜けたか」が人によって違う物差しになっているからです。ここだけは設計を変える必要があります。

## 2. 測ったこと

### 技の選択は、能力値より強い

同じモンスターで技3つの組み合わせを全通り試し、**能力値が5%高い相手**（既定セット）と戦わせました。

```
10通りの技構成のうち最良: 勝率 93.3%  ［テールスイープ・ダブルゴア・ウォーターヒール］
```

**5%弱いのに93%勝ちます。** 反射＋回復＋攻撃という組み合わせが、殴り合いしかしない相手を崩します。

能力値が互角の相手でも、技構成だけで勝率が **28%〜67%（39ポイント幅）** 動きました。

**つまり、意思決定で勝てるゲームになっています。**

### ところが、既定セット同士だと能力値で決まってしまう

両者が既定セットのまま戦うと、わずかな能力差が致命傷になります。

```
能力+1%  → 勝率 64.3%
能力+2%  → 勝率 70.3%
能力+3%  → 勝率 79.0%
能力+5%  → 勝率 87.7%
能力+8%  → 勝率 99.7%
```

**8%差で事実上100%です。** HP・攻撃・防御が同時に上がると、1発のダメージとHPの両方で差がつき、交換のたびに差が開くためです。

単一の能力だけを+15%したときの勝率は、攻撃 92% > HP 83% > 魔力 74% > 防御 71% > 素早さ 64%。**攻撃力が突出しています。**

### 1戦はおよそ7ターン

スターター総当たりの平均は7.0ターン。**1戦あたりの意思決定は7回**です。短すぎはしませんが、組み立てを見せるには足りません。

### 強くしても、アリーナは同じ距離で止まる

100戦ラダーを2000回ずつ。

```
スターター        到達中央値 3戦
6代融合（総合416）到達中央値 5戦
14代融合（総合339）到達中央値 1戦
```

**14代融合が6代融合より弱い**のは、融合が能力を単調に上げないためです。そして敵は「入場したモンスターの何倍」で作られるので、**強くしても敵も強くなり、到達距離は変わりません。**

## 3. 競技性のために必要なこと

### 3-1. 敵の強さを「相対」から「絶対」へ（最優先・必須）

現在 `strengthFor()` は `statTotal(player.stats) × 倍率` で敵を作ります。プレイヤーが2倍強くなれば敵も2倍になります。

**この設計では、何を比べても個人の運しか測れません。** ランキングを作る前に、ここを直す必要があります。

直し方は1か所です。基準をプレイヤーではなく**固定のカーブ**にします。

```
第1戦   総合 200    ← 誰が来ても同じ
第5戦   総合 320
第6戦   総合 420（ボス）
第50戦  総合 900
第100戦 総合 1800（竜）
```

こうすると「80戦まで行った」が全員にとって同じ意味になり、**育成が初めて意味を持ちます**（強いモンスターは実際に遠くまで行ける）。

副作用として、弱いモンスターは序盤で詰みます。入口に「推奨総合値」を出すか、育成用の低難度ラダーを別に用意するのが自然です。

### 3-2. リプレイ検証（不正対策・ほぼ実装済み）

**coreはすでに完全に決定的です。** 乱数はすべて `context.rng` とrun IDから導かれ、`Math.random` はどこにも入っていません。

つまり **「シード＋行動列」だけで戦闘を完全に再現できます。**

```ts
{ runId, monsterGenes, loadout, actions: ['attack','defend',{skill:'...'},...] }
```

サーバーはこれを受け取って**同じ計算を再実行**すれば、申告された記録が本物か判定できます。スコアを信用する必要がありません。**オンラインランキングを作るなら、この性質が最大の資産です。** 設計を変える前に壊さないでください。

### 3-3. 全員同じ盤面（週替わりラダー）

run IDを「その週のシード」にすると、**世界中が同じ100戦と同じドロップ**に挑みます。運の差が消え、比べているものが腕前になります。

サーバーなしでも成立します（同じシードなら同じ敵が出る）。サーバーは記録の集約だけを担当します。

## 4. 戦略性のために必要なこと

### 4-1. 技を選ばせる（最も効果が大きく、最も安い）

**勝率を39ポイント動かす選択を、ゲームは一度も尋ねていません。** 既定セットが自動で入り、そのまま戦えてしまいます。

- アリーナ入場前に「3枠を決める」工程を必ず通す
- 各戦のあいだ（全回復のタイミング）で組み替えられる ← **相手を見てから変えられると、ここが読み合いになります**
- 技説明にすでにある期待ダメージを、選択画面でも見せる

core側は全部揃っています（`getLearnableMoves` / `validateMoveLoadout` / `expectedDamage`）。UIの導線だけの話です。

### 4-2. 敵AIを強くする

現在の `createBasicPolicy` は**期待ダメージが最大の技を選ぶだけ**です（回復は追加しました）。だから反射を置くだけで崩れます。93%の勝率はAIの弱さでもあります。

競技として見せるなら、少なくとも：

- 反射中は殴らない
- 相手が瀕死なら確実に倒せる手を選ぶ
- 状態異常が効く相手かどうかを見る（物理型に暗闇、など）
- 自分が有利な属性の技を優先する

**強いAIは、プレイヤーの選択に意味を与えます。** 弱いAIに対する最適解は1つしかなく、それは戦略ではありません。

### 4-3. 能力値の崖をならす

+8%で100%になるのは急すぎます。ダメージ式が `攻撃/(攻撃+防御)` でHPの差と掛け算になるため、差が3重に効いています。

`damageScale` を下げて1戦を長くする（7→10ターン程度）だけでも、**選択が結果をひっくり返せる帯域が広がります。** 数値はいただいたものなので、こちらでは変えていません。

### 4-4. 融合に意思を入れる

今の融合は「2体を選ぶ」だけで、結果はほぼ遺伝任せです。パーツで1部位を固定できますが、プレイヤーが狙って組み立てる余地は狭いままです。

- どの技が欲しいかから逆算できるよう、**部位→技の対応を融合画面に出す**（`getLearnableMoves` の `reason` がすでに持っています）
- パーツを1回の融合で2個使えるようにする（`partsPerFusion` は設定値です）

これは「次に何を作るか」という、戦闘の外側の戦略になります。

## 5. 優先順位（費用対効果の順）

| | やること | 効果 | 規模 |
|---|---|---|---|
| 1 | 入場前に技を選ばせる／戦闘間で組み替え | 戦略性が**今すぐ**立ち上がる | UIのみ・小 |
| 2 | 敵の強さを絶対カーブに | 競技性の**前提条件** | core・中 |
| 3 | 敵AIの強化 | 選択に意味が出る | core・中 |
| 4 | 週替わりシード＋リプレイ記録 | ランキングの土台 | core小＋サーバー |
| 5 | 能力値の崖をならす | 逆転の帯域が広がる | 設定値1行＋再測定 |
| 6 | 融合画面に部位→技を出す | 育成の戦略 | UIのみ・小 |

**1と6はUIだけで、今日中に入れられます。2と3がゲームの骨格を変えます。4はサーバーの話です。**

## 6. ログイン・ランキングについて

ランキングには最低限これが要ります。

- **プレイヤー識別** — まずはローカルのプレイヤー名で足ります。ログインは「記録を別の端末から見たい」「名前を取られたくない」が出てから
- **記録の保存先** — 現在このゲームは**何も永続化していません**（リロードで全部消えます）。ランキング以前に、まずローカル保存が要ります
- **検証** — 3-2のリプレイ。これがないと自己申告のスコアしか集まりません

**順番としては、ローカル保存 → プレイヤー名 → ベスト記録の表示 → サーバー集約、です。** 最初の3つはサーバーなしで作れて、そのままランキングの入力になります。
