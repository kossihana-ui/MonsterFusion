# 連勝の世界ランキング：何が必要か

2026-11-14。「連勝の世界ランキング的なものがあるといい」への回答です。**ローカル側は実装済みで、残りはサーバーの話**です。

## 1. もう動いている部分

| | 状態 |
|---|---|
| プレイヤー名 | ✅ アリーナ入口で入力・保存（`src/shared/record.ts`） |
| 連勝数の記録 | ✅ 敗北・リタイア・制覇の3種を記録 |
| 自己ベストの表示 | ✅ 入口に表示 |
| 直近20戦の履歴 | ✅ 保存のみ（表示は未実装） |
| サーバー送信 | ❌ 未実装 |

保存先はブラウザのlocalStorageです。**この端末・このブラウザでしか見られません。** 保存しているデータの形は、そのままサーバーに送れる形にしてあります。

```ts
{ wins: 12, monster: 'Noxra', ending: 'retired', at: 1794612739395 }
```

## 2. ランキングを作る前に決める2つのこと

### 2-1. 何を競うのか

連勝数だけだと、**現状では運の比べ合いになります。** 敵がプレイヤーの強さに合わせて作られるため、強く育てても到達距離が変わらないからです（[COMPETITION_AND_DEPTH.md](COMPETITION_AND_DEPTH.md) の2章に測定値）。

ランキングを入れるなら、先に **敵の強さを絶対カーブにする**必要があります。これをやらずにランキングを出すと、1位は「いちばん運が良かった人」になります。

### 2-2. 全員が同じ条件で戦うか

**週替わりシードを強くおすすめします。**

- 今週のシードは全員同じ → **同じ100戦、同じ敵、同じドロップ**
- 比べているものが腕前と育成になる
- 「今週は何連勝？」という話題が毎週生まれる

coreのアリーナは `run.id` からすべての乱数を導いているので、**シードを週の値に差し替えるだけ**で実現できます。新しい仕組みは要りません。

## 3. 不正対策：すでに解決しています

**coreは完全に決定的です。** 乱数はすべて `context.rng` と `run.id` から導かれ、`Math.random` はどこにも使っていません。これはテストで固定されている性質です。

つまりクライアントは**スコアではなく「手順」を送れます。**

```ts
{
  seed: '2026-W46',          // その週のシード
  monster: { genes, tier },  // 入場した個体
  loadout: ['final-tail', 'fang-bite', 'power-slam'],
  actions: ['attack', 'defend', { kind: 'skill', skillId: 'final-tail', charge: 93 }, ...],
}
```

サーバーはこれを**同じcoreで再実行**して、申告された連勝数が本当に出るか確かめられます。**スコアを信用する必要がありません。**

サーバーはNode製でよく、coreをそのままimportできます（`runBattle` と `createArenaEnemy` があれば足ります）。改造クライアントで「999連勝」と送っても、再実行すれば合いません。

ただし次の2点は別途必要です。

- **入場した個体が正当か** — 融合・ソウルメイクの履歴も同じ方法で再実行して検証するか、サーバー側でコレクションを持つ
- **連打数の上限** — ファイナルテールは連打数がそのままダメージです。マクロで10000回送られないよう、`chargeSeconds` × 人間が押せる上限（毎秒15回程度）で頭打ちにするのが無難です。**現在coreに上限はありません**

## 4. ログインについて

**順番としては後回しで構いません。**

| 段階 | 必要なもの | できること |
|---|---|---|
| 今 | なし | 自己ベストを自分で更新する |
| 次 | サーバー＋端末ごとのランダムID | 世界ランキングに名前が載る |
| その次 | ログイン | 機種変更で記録を引き継ぐ、名前を守る |

**端末ごとのランダムIDだけで、ランキング自体は成立します。** ログインが要るのは「別の端末から見たい」「名前を取られたくない」という要求が出てからです。

名前の重複・不適切な名前の扱いは、ログインより先に決める必要があります（表示名＋#1234 のような形が簡単です）。

## 5. 最小構成の提案

1. **週替わりシード**（core小・サーバー不要）— これだけで「今週の記録」をローカルで比べられます
2. **絶対カーブ**（core中）— ランキングの前提
3. **連打数の上限**（core小）— 送信前に必要
4. **記録の送信と再検証**（サーバー）— Node1本、coreをimportするだけ
5. **ログイン**（必要になってから）

**1と3はcoreだけで今日できます。** 2はゲームの手触りが変わるので、入れるかどうかのご判断が要ります。
