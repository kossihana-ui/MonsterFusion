## あなたがやること

### ① Supabaseでプロジェクトを作る

1. https://supabase.com にサインアップ（GitHubアカウントで入れます）
2. 「New project」
   - **Name** … 何でもいい（`monsterfusion` など）
   - **Database Password** … 強いものを。**私には見せないでください。**
     このパスワードは管理用で、ゲームは一切使いません
   - **Region** … `Northeast Asia (Tokyo)` が近いです
3. 数分待つ

無料枠で足ります（データベース500MB。セーブ1件はせいぜい数十KBです）。

### ② テーブルと関数を作る

1. 左メニューの **SQL Editor**
2. このリポジトリの [`supabase/saves.sql`](../supabase/saves.sql) を**全部**貼る
3. **Run**

何度実行しても同じ結果になるように書いてあります。失敗したらエラーをそのまま
教えてください。

できるもの：

- `saves` テーブル（1アカウント1行）
- `save_pull` / `save_push` の2つの関数
- **テーブルへの直接アクセスは全面禁止**（RLSを有効にして、ポリシーを1つも
  作っていません）。ブラウザができるのは上の2つの関数を呼ぶことだけです

### ③ 鍵を2つ取る

左メニューの **Project Settings → API**：

- **Project URL** … `https://xxxxx.supabase.co`
- **anon public** の鍵 … 長い文字列

> `service_role` の鍵は**絶対にコピーしないでください。** あれは全権限の鍵で、
> ブラウザに置いたら誰でもすべてのセーブを読み書きできます。使うのは
> **anon** だけです。

### ④ GitHubに鍵を入れる

リポジトリの **Settings → Secrets and variables → Actions → New repository secret**、
2つ作ります。

| Name | Secret |
|---|---|
| `SUPABASE_URL` | ③のProject URL |
| `SUPABASE_ANON_KEY` | ③のanon public |

名前はこの綴りのままにしてください。`.github/workflows/pages.yml` がこの名前で
読みます。

### ⑤ 手元でも試すなら

```bash
cp .env.example .env
```

`.env` に同じ2つを書きます。**`.env` はコミットされません**（`.gitignore`済み）。

## 鍵がないあいだ

**ゲームは今までどおり動きます。** `supabaseKeys()` が `null` を返し、同期層が
まるごと黙るだけです。セーブはこのブラウザのlocalStorageに残ります。
`scripts/check-save-sync.mjs` はこの「鍵がない状態」も検証しています。

## anon鍵が公開されることについて

anon鍵は**公開前提の鍵**です。Supabaseを使うページには必ず入っています。
隠すものではありません。守っているのは鍵ではなく、**その鍵で何ができるか**です。

- テーブルには触れません（RLS有効、ポリシーなし）
- 関数は2つだけ
- どちらの関数も**合言葉を要求します**。読むほうもです。IDだけ知っていても
  他人のセーブは読めません
- 合言葉はbcryptハッシュで保存され、平文では残りません
- 書き込みは「いま入っている `revision` の上に書く」ものだけ通ります。
  2台が同時に押しても、両方勝つことはありません

残っている弱点を正直に書いておきます：

- **回数制限がありません。** 誰かが延々と `save_push` を叩けば、無料枠を
  使い切らせることはできます。Supabase側のRate Limitingか、
  Cloudflare経由にするかは、人が増えてからの話だと考えています
- **アカウントの復旧手段がありません。** 引き継ぎコードを失くしたら、その
  セーブは誰のものでもなくなります。メールアドレスを預からない代わりの
  当然の帰結で、入口の軽さと引き換えです

## 2026-11-15 追記：つながりました

鍵が入り、画面ができ、**公開サイトで実際に端末をまたぎました。**

確認したこと（公開サイト上、実際のSupabaseに対して）：

- 片方でアカウントを作って「今すぐ同期」→ `この端末のセーブを送りました`
- ブラウザの保存を全部消して（＝別の端末）、コードを入れて同期
  → `もう一方の端末のセーブを読み込みました`
- **乱数の位置まで一致しました。** これが一致するということは、同じ続きが
  同じ乱数で進むということです
- 分岐させて同期 → 選択画面が出て、**何も書き込まれませんでした**
- 「こちらを残す」→ revision 2 として送信。もう一度同期 → `どちらも同じでした`
- スマホ幅375pxで横スクロールなし、ボタンは全部44px

**途中でバグが1つ見つかって、直しました。** 一度セーブを受け取った端末が、
そのあと自分の進行を送れなくなっていました（`どちらも同じでした` と言い続ける）。
**同期の半分が動いていませんでした。** 手元のテストでは見つからず、
公開サイトで実際に2台ぶん動かして出ました。いまは検証スクリプトに入っています。

### 残っているもの

テスト用のアカウントの行が `saves` テーブルに数件残っています。消すなら
SQL Editorで：

```sql
delete from public.saves;
```

**本物のセーブもこれで消えます。** いまは誰も遊んでいないので問題ありませんが、
公開して誰かが遊びはじめたら、この1行は二度と実行しないでください。
