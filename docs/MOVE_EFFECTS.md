## 2. 防御貫通と砕牙

ご指示どおり**2つを別物として分離**しました。

砕牙は**低威力の技が枠を取るに値する理由**として付けました。小さいが、相手がどれだけ硬くても同じだけ通ります。

**名称について**: 「砕凱」と書かれていましたが、変換候補として自然な **砕牙（さいが）** を採用しました。別の字をお考えでしたら直します。コード上の識別子は `shattersDefense` なので、表示名の変更はUI側だけで済みます。

## 5. 実装で気づいて直した2点

**1. このターンに付与した状態が、同じターンの終わりに消えていました。** 1ターンのバフが使われる前に切れ、硬直も本来止めるはずのターンの前に解けていました。`appliedTurn` を持たせ、付与されたターンは減算しないようにしています。

**2. 条件判定は解除の前に行う必要がありました。** `coil-crush` は「バインドなら2倍、そのバインドを解除」なので、順序を逆にすると2倍が永久に乗りません。判定を先に固定しています。

## 6. UI側への影響（要対応）

**`scripts/check-battle-ui.mjs` が落ちるようになりました。** core側の不具合ではありません。

敵（Moss）が `bind-whip` と `pollen-burst` を覚えるようになったため、**1ターン目に守ったあと、20回中12回でプレイヤーが状態異常を受けます**。バインドされていると2ターン目に技を撃てないので、「2ターン目に必ず大技が撃てる」という前提が崩れました。

これは**新しい仕組みが働いている証拠**です。チェック側を、

- 敵を `createScriptedPolicy([{ kind: 'defend' }])` に固定する、または
- バインドされなかったシードを使う

のどちらかにしてください。

### 効果中のデバフは再付与できません（2026-10-28変更）

**かかっている最中のデバフに、同じデバフを重ねられません。** 残りターンは増えず、リセットもされません。切れたあとなら、また入ります。

```ts
canApplyStatus(statuses, 'blind')   // すでに暗闇なら false
```

仕様で「暗闇2ターン」「バインド1〜2ターン」と**期間を決めている**のに、毎ターン撃ち直せばその期間が意味を持たなくなるためです。暗闇を続けさせたいなら「最近かけた」状態である必要があり、払い続ければよいわけではありません。

**バフは今までどおり上書きできます**（長い方のターン数が残る）。バフを維持するコストは「攻撃しなかったターン」としてすでに払われているので、同じ制限をかけると二重に取ることになります。

## 8. イベント

`BattleLogEntry.effects` に `damage / heal / mp / cleanse / status / noEffect / miss / skip / blocked` が順番に入ります。**既存フィールドはそのまま**です。

- 多段攻撃は `hit` / `hits` で1発ずつ
- `miss` の `reason` は `'blind'`（暗闇）か `'chance'`（成功率・回避）
- 反射は「相手が自分を攻撃した」damage イベントとして返ります
- 即死は `critical: true` の1発として返ります
- `heal` の `amount` はHP上限で切った実回復量。0はHP満タン
- MP回復は `heal` ではなく `mp` イベント（10章）

### `noEffect`（新規）

```ts
{ type: 'noEffect', actorId, targetId, skillId?, status, reason: 'alreadyActive' }
```

**状態異常がかかろうとして、かからなかった**ときに出ます。すでに同じデバフがかかっていた場合です。

- **状態異常の表示は変えないでください。** すでに付いているものがそのまま続いています
- 文字だけ出す想定です（「すでに暗闇だ」など）
- **「技が何も起こさなかった」ことが分かる唯一のイベントです。** これを無視すると、プレイヤーには理由が見えません
- `status` イベントと同時には出ません。どちらか一方です

知らないイベント型を無視する作りであれば、そのままでも壊れません（状態異常バーが動かないのが正しい挙動です）。

## 9. 回復は術者の魔力で増減します（2026-10-28）

**ウォーターヒールの回復量は、使った個体の魔力で変わります。**

```ts
getMoveHealing('hydro-ram', monster)   // その個体の回復量（HP上限で切る前）
```

技説明・図鑑はこれを使ってください。`getMoveBehavior(skillId).heal` は**技が名乗っている数値（30）**で、個体の回復量ではありません。

### 計算

```ts
DEFAULT_BATTLE_CONFIG.healScaling
// { referenceMagic: 70, perMagic: 0.1, minRatio: 0.8, maxRatio: 1.2 }
```

魔力70で技どおりの30。そこから魔力10につき1増減し、技の名乗る値の0.8〜1.2倍（30なら24〜36）で止まります。四捨五入した整数です。

上下限は**HPの実数ではなく技の値に対する倍率**にしています。2つ目の回復技を足したときに、この数値の意味が変わらないようにするためです。

**実測した範囲**（ルートモンスター400体、魔力21〜130）

```
25HP x1   26HP x5   27HP x14  28HP x33  29HP x61  30HP x54
31HP x49  32HP x62  33HP x53  34HP x48  35HP x14  36HP x6
```

スターターは Moss 32（魔力86）、Aqua 30（魔力68）、Ignis 28（魔力46）です。

### 回復だけでは決着しません

`heal.amount` は**HP上限で切り詰めたあとの実回復量**です（従来どおり）。HP満タンなら0です。

回復しかしない個体を、攻撃してくる相手に200戦ぶつけました。

```
魔力  20（回復25）  相手の勝ち 200/200   平均6.0ターン
魔力  70（回復30）  相手の勝ち 200/200   平均6.0ターン
魔力 130（回復36）  相手の勝ち 200/200   平均6.0ターン
魔力9999（回復36）  相手の勝ち 200/200   平均6.0ターン
```

**どの魔力でも1戦も引き延ばせません。** 連続使用不可があるため実質2ターンに1回で、ダメージが上回ります。上限36は保険として残していますが、現状それが効く前に決着しています。

## 10. MPの回復には専用イベントがあります（2026-10-28）

```ts
{ type: 'mp', actorId, targetId, skillId?, amount }
```

**以前はMP回復が `heal` イベント（`amount: 0`）として出ていました。** 「`amount: 0` はHP満タン」という表示にすると、マルチゲイズを撃つたびに「HP満タン」と出てしまいます。別イベントに分けました。

`amount` はMP上限で切り詰めたあとの実回復量です。該当するのはマルチゲイズ（MP10回復）だけです。

## 11. 種（seed）

**種を付けた本人が追撃したときだけ**払い出されます（2026-10-28確定）。

| 追撃の属性 | 効果 |
|---|---|
| 炎 | その技が**1.5倍** |
| 水 | 相手を**バインド** |
| その他 | 何も起きない。種は残る |

```
  炎属性  種なし  ダメージ 5   状態: なし
  炎属性  種あり  ダメージ 7   状態: なし        ← 1.5倍
  水属性  種あり  ダメージ 5   状態: バインド     ← 拘束
  土属性  種あり  ダメージ 4   状態: 種          ← 対象外なので残る
```

**種は1回で消えます。** 多段攻撃でも払い出しは1回です。他人が攻撃しても払い出されません（種を付けた本人のIDで判定しています）。

これは特定の技の性質ではなく「種を付けた相手を自分で殴ったとき」のルールなので、技の定義ではなくターン処理に置いてあります。設定は `DEFAULT_BATTLE_CONFIG.seedPayoff` です。

## 12. 倍率の表示（×2倍の演出用）

ダメージイベントに **なぜ大きくなったか** が入ります。UIで倍率を計算し直さないでください。

```ts
{ type: 'damage', amount: 15, ...,
  boostTotal: 3,
  boosts: [
    { source: 'attackUp', reason: '攻撃力上昇', factor: 2 },
    { source: 'seed',     reason: '種',       factor: 1.5 },
  ] }
```

実測:

```
通常            ダメージ  4   ×1
攻撃力2倍        ダメージ 10   ×2    攻撃力上昇×2
種（炎で追撃）    ダメージ  5   ×1.5  種×1.5
攻撃力2倍＋種     ダメージ 15   ×3    攻撃力上昇×2 / 種×1.5
```

`boosts` が空（または無い）なら通常のヒットです。**演出を出す条件は `boostTotal > 1` で判定できます。**

`reason` は日本語でそのまま表示できます。`source` は演出の出し分け用の識別子です。属性倍率も `source: 'element'` として同じ配列に入ります（1.0のときは入りません）。

## 2026-11-15 追記：跳ね返しとバインドの値段

遊んでもらった報告は **「跳ね返しわざと、バインド技が結構強い」**。測りました。
**合っていました。**

### 測り方

同じ個体を両側に置き、技だけを変えた鏡合わせです。**50%なら、その技は枠の
ぶんだけの働き**をしていることになります。

### バインド（60%で相手が行動できない）

アクア（`death-bite` / `magic-eye` を覚える）を、バインドを抜いた自分自身に
当てました。300〜400回。

```
bindChance   アクアの勝率
0.6（現在）     76%
0.45            63%
0.35            54%
0.25            42%
```

**76%です。** 行動できない1ターンは、技が配れるものの中でいちばん強く、
それが**威力をそのまま持った攻撃技のおまけ**として付いています。
`death-bite` は貫通と毒も一緒に持っています。

### 跳ね返し（`tail-sweep`）

これは鏡合わせでは**測れませんでした**。家のAIは跳ね返しを使いません
（ダメージが0の技は `expectedDamage` にとって価値0）。しかも**避けもしません**。
毎回まっすぐ突っ込みます。つまりこの技は、**人間の手の中でだけ強い**。

そこで、跳ね返しと最良の攻撃を交互に打つ人 対 家のAI、同じ個体・同じ技で：

```
                        勝率
跳ね返しを使わない        58%
跳ね返しを使う（現在）     80%   ← 一手で +22ポイント
  reflectShare 0.75      74%
  reflectShare 0.5       66%
  reflectShare 0.25      49%
```

### 直したもの（数字は変えていません）

`BIND_CHANCE = 0.6` と `BIND_EXTEND_CHANCE = 0.2` は技表の横に**直書き**でした。
隣の `statusTurns` や `flinchChance` は設定から来ているのに、この2つだけが
コードの中にありました。**「確率はハードコードしない」に違反していました。**

- `battle.bindChance`（0.6）／`battle.bindExtendChance`（0.2）へ移動
- `battle.reflectShare`（1）を新設。跳ね返しが返す割合です
- 既定値はそのままなので、**遊びは1ミリも変わっていません**

`bindChance` は技表を組むときに一度読むので、差し替えるには既定値を変えます
（`statusTurns` や `powerSteps` と同じ作りです）。`reflectShare` は戦闘ごとに
読むので、設定を渡せばその場で変わります。

### 残っている判断

**下げるかどうかは決めていません。** 「アクアは技で戦う個体」が狙いなら76%は
正解かもしれず、それは数字ではなく設計の話です。下げるなら、測った範囲では
`bindChance` 0.35〜0.45、`reflectShare` 0.5 あたりが「強い技」に収まります。

もうひとつ、**家のAIが跳ね返しを使わず、避けもしない**のは別の問題です。
技を弱くしても直りません。AIが跳ね返しを張った相手に攻撃を続けるかぎり、
この技は人間側の一方的な得になります。
